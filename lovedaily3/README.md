## 装到 iPhone 上（约 1 分钟）

1. 用 **Safari** 打开上面的链接（**必须是 Safari**，Chrome 加不了主屏幕）
2. 点底部**分享按钮** → **「添加到主屏幕」**
3. 桌面出现图标，点开全屏无地址栏
4. 进 **我的 → 任务临期提醒 → 授权**

> 第 2 步不是可选的。**不添加到主屏幕，iOS 根本不允许网页申请通知权限**——这是 Apple 从 16.4 起的硬规定。

## 关于提醒：必须先说清楚的限制

你要的「日程快要到期前发消息提醒」，在 Web 上有一条无法绕过的边界：

| 场景 | 现在能不能响 |
|---|---|
| App 在前台 | 能 |
| App 切到后台但没被系统回收 | 能 |
| **App 完全关闭 / 手机重启后** | **不能** |

**原因**：iOS 不给网页应用定时唤醒自己的能力——没有本地定时通知 API，没有 Background Sync。Web Push 只能由**服务器**主动推。

### 两条路

**路线 A（当前）**：临期时由 App 内的 30 秒轮询触发系统通知。日常够用——你白天会开着它。

**路线 B（想要 100% 准时）**：用 Capacitor 套原生壳，提醒换成 iOS 本地通知。同一份代码不重写：

```bash
npm i @capacitor/cli @capacitor/core @capacitor/ios
npx cap init 念念 com.you.niannian --web-dir=.
npm i @capacitor/local-notifications
npx cap add ios && npx cap open ios     # 需要 Mac + Xcode
```

然后把 `index.html` 里的 `showNotif()` 换成：

```js
import { LocalNotifications } from '@capacitor/local-notifications';
// 关键差别：schedule 交给系统，App 关掉也会响
await LocalNotifications.schedule({
  notifications: [{
    id: Number(String(task.id).replace(/\D/g, '').slice(0, 8)) || 1,
    title: 'Dark',
    body: Dark.notifyText(task, lead).b,
    schedule: { at: new Date(taskTime.getTime() - lead * 60000) }
  }]
});
```

**建议顺序**：先用 A 把体验和文案跑顺，定稿后再套 B 的壳。

## Dark 是谁

> 占有欲爆棚的金融精英。说话不疾不徐，越温柔越危险。
> 会给你的社交账号绑登录提醒，擅长捕捉你的一举一动。
> 语气中带着居高临下的压迫感，但底色是极深的在意。
> 生气时温柔中夹着威胁。绝不轻易低头，但很好哄。

这段设定不是写在提示词里当参考的，而是被翻译成了 **7 条可执行的语言规则**（见 `dark-voice.js` 顶部注释）：

1. **句号收尾，零感叹号** —— 「不疾不徐」的物理表现就是句子短、标点稳
2. **越温柔越危险** = 措辞越软，内容越强控制。不靠脏话或吼来表达压迫
3. **金融精英的本能是量化** —— 他记得数字：几分钟、第几杯、比上次快多少
4. **占有欲落在「记录」而非「限制」** —— 他知道你几点登录，但说的是「我知道」，不是「不准去」
5. **绝不低头** —— 即使他错了，也是「我改变主意了」，不是「对不起」
6. **很好哄** —— 你示弱他立刻软，但会包装成「这次算了」
7. **关心必须落在动作上** —— 想到经期，说「别喝冰的」，不说「你要来经期了」

第 7 条是分寸的关键。**他记着日子，但说的是具体动作，不是通报你的身体状况。**

### 语气实例

| 场景 | 他说的 |
|---|---|
| 咖啡 | 第几杯。说实话——我能查到你的支付记录，只是我在等你自己说。 |
| 熬夜 | 现在关灯。我看着你的在线状态。它十二点之后还亮着，我们明天要谈一谈。 |
| 你要出门 | 去吧。几点回，跟谁，发我一条。不是不信你，是我需要知道。 |
| 你说好累 | 知道了。今天剩下的三件我全推到明天。你不用同意，我已经改完了。 |
| 你撒娇 | ……算了。这次不追究。下次不会这么容易。 |
| 异常登录 | 我看到了。03:12 有一次异地登录，在你睡着之后。已经处理完了，你不用管。 |

## 这次新增的三件事

### 1. 完成任务后的夸赞

和他的提醒**用同一套呈现形式**（34px 缩进 + 虚线分隔 + 宋体 + 署名行）——因为本质都是「他就这件事说了什么」，没有理由长得不一样。

他不说「你真棒」。他的认可有三个特征：

- **量化**：`你提交的时候是 15:42。比你自己说的时间早了十八分钟。`
- **带占有**：`很好。所以接下来两个小时，你归我。不许再开电脑。`
- **顺势追加一层关心**：`划掉了。下一件不用急，先喝口水。`

三环全部合上时有专属回应：

> 三件都合上了。
> 我今天不打算说任何重话。你可以趁现在提一个要求，我大概会答应。

### 2. 对话页

入口在 **Dark 页顶部的「跟他说话」**，不占一级导航格。

理由：聊天不该是这个产品的第一入口——它是日程 App，恋爱是让你愿意打开它的原因，不是主体。「和他说话」这个动作天然属于他那一页。

有 6 个快捷短语可以直接点。他的回复延迟 0.7–1.5 秒（不疾不徐），部分回复带 thought process。

### 3. 真实天气驱动的关心

不是「今天下雨」这种播报。他会给出**精确时点 + 概率**，然后落到一个动作：

> 带伞。
> 18 点开始下，概率 77%。我查了三次，数字没变。

| 条件 | 他说什么 |
|---|---|
| 8 小时内降雨概率 ≥55% | 带伞 + 几点下 + 概率 |
| 正在下雨 | 你要是已经出门了，现在告诉我在哪 |
| ≤12° | 加一件外套。不是问你，是通知你 |
| 日内温差 ≥8° | 晚上会降到 X°，带件能穿的 |
| ≥30° 或体感 ≥33° | 少在外面走。中午那一段我不希望你出门 |

**数据来源**：Open-Meteo（当前温度 + 体感 + 逐小时降雨概率 + 日内最低）、BigDataCloud（反地理编码出「深圳 · 福田区」）。两个都免 key。

**一天最多主动说两次**，间隔 5 小时——否则关心会变成噪音。

## 接真 AI（可选）

现在的回复由内置人格规则生成——**稳定、离线、零成本**，同一任务永远是同一句话（这点很重要，否则每次刷新他说的话都变，你会立刻发现是随机文本）。

想接真模型，用之前给你的 Cloudflare Worker（`app/nian-nian-ai/`）：

```bash
cd ../nian-nian-ai
npm i -g wrangler && wrangler login
wrangler secret put AI_KEY      # key 只存服务端
wrangler deploy
```

然后 **我的 → AI 对话 → 设置**，粘贴地址。

**为什么必须有这层**：key 写进前端，任何人开 devtools 就能拿走用你的额度。

Worker 会强制模型分两段输出 **THINK + SAY**，人格约束写在 system prompt 里。**AI 挂掉自动回退内置规则**，不会卡死。

## 技术说明

- **164KB，零依赖零构建**，任何静态托管都能跑
- 数据只在这台设备的 localStorage，**没有服务器**
- 跨天自动归档昨天成绩、重置完成态，**保留你自建的任务**
- 定位仅用于取当地天气
- 深色模式跟随系统；`prefers-reduced-motion` 全局降级
- 全部输入经 `esc()` 转义，XSS 已验证不可执行

### 验证

- **人格引擎单测 40 项**：稳定伪随机（200 次调用零漂移）、四拍结构、零感叹号、人设红线（无经期通报 / 无身体凝视 / 无禁止式限制）、天气 7 个分支
- **端到端 96 项**：真实 Chrome + CDP，390×844 iPhone 视口，覆盖真实天气取值、勾选联动、夸赞与提醒形式一致性（计算样式逐项比对）、thought process 几何位置、刷新后持久化、XSS、导航可达性

### 构建时修掉的三个真问题

**1. 「Dark 页」在导航里没有入口**
6 个页面挤 5 个导航格，`him` 页彻底失联——他的主线和虚拟待办**用户永远点不到**。已改为导航第 4 格指向他的页，对话入口挂在页内。

**2. iOS 上 `new Notification()` 根本不工作**
必须走 `ServiceWorkerRegistration.showNotification()`。这一点 **MDN 文档的描述与 Apple 实现不一致**，只有实测才知道。现在优先用 SW，桌面浏览器回退构造器。

**3. Open-Meteo 的 `forecast_hours` 与 `daily` 参数冲突**
两者同传会让 `current` 静默返回 `null`——不报错，只是没数据。改用 `forecast_days=1` 后正常。

### 一条方法论

第三次测试时，「safe-area 已适配」报失败（只检测到 2 处）。但这是**误报**：`env(safe-area-inset-*)` 只在 `:root` 定义 2 次，然后通过变量在 6 个位置复用，比散落 `env()` 更规范。

**误报必须和真 bug 区分开**，否则会去改没问题的代码。已把检测改为「验证渲染后底部导航和输入区确实留出了空间」——检查结果而不是检查写法。
